# rekordbox・USBライブラリと既存波形の取り込み

rekordboxの既存ライブラリをブラウザ内で読み取り、BPMの再解析をせずDECKFLOWへ引き継ぎます。元DB・解析ファイル・音源は変更せず、選択したファイルをサーバーへアップロードしません。CDJ用USBの**読み込み**はWeb版で行い、**書き出し**には別途Mac補助ツールを使います。

## フォルダまたはUSBから開く

1. PCのライブラリを読む場合は、rekordboxを終了してDBへの書き込みを終えます。
2. 楽曲管理の左側にある **ライブラリを開く → フォルダ・USBを選択** を押します。
3. `master.db` を含むフォルダ、またはUSBのルートフォルダを選びます。複数のDB／XMLがある場合は、読み込むファイルを選択します。
4. 元音源が選択した範囲外にある場合は、同じ画面で続けて音源フォルダを選びます。
5. **読み込んでキャッシュ** を押します。メタデータを先に表示し、対応する解析ファイルと音源を順番に保存します。

USB接続を自動検出する機能ではありません。接続後にブラウザの選択画面から指定してください。iPadでは「ファイル」に表示される外部ドライブを選びますが、フォルダ選択の可否はOS・ブラウザに依存します。フォルダ選択が使えない場合は **DB・XMLファイルを選択** を使い、取り込み後に各曲の **音源を選択** で関連付けてください。DBファイルだけでは曲の音源は含まれません。

## 対応形式

| 形式 | 曲・プレイリスト | グリッド・波形・CUE |
| --- | --- | --- |
| rekordbox 6/7 `master.db` | 曲名、アーティスト、平均BPM、長さ、元パス／ID／サイズ、通常プレイリストと階層 | DB内のHOT CUE A〜H、メモリーCUE／LOOP、名前。DBが参照するANLZから波形・ビートグリッドを追加 |
| USBの従来Device Library `PIONEER/rekordbox/export.pdb` | 曲情報、プレイリスト、曲順と階層 | DBが参照するANLZから波形・ビートグリッド・対応CUE／LOOP・名前／HOT CUE色 |
| USBのOneLibrary／Device Library Plus `exportLibrary.db` | 曲情報、通常プレイリスト、曲順と階層 | CUE／LOOPはDBのcueテーブルではなく、対応するANLZから取得 |
| rekordbox XML | 曲名、アーティスト、平均BPM、長さ、追加日、Location／TrackID／Size、プレイリストと階層 | 複数TEMPOの開始位置・BPM・拍子・小節内拍、HOT CUE A〜H、メモリーCUE／LOOP、名前／RGB色。音源・波形本体は含まない |

`master.db` と `exportLibrary.db` は、対応するSQLCipherの復号とSQLiteの読み取りをWeb Worker内で行います。SQLや外部プログラムを実行するインポーターではなく、既知の構造を読み取ります。暗号形式や列構成の変更、破損ファイルには対応エラーを返します。

PCのDBは未反映の変更を含まない状態が必要です。同時に選んだフォルダ内に非空の `master.db-wal` などがあると取り込みを停止します。rekordboxを終了してDBへの反映を終え、フォルダを選び直してください。確定できない場合はrekordboxからXMLを書き出します。DB単体の選択では、選択していない隣接WALの存在をブラウザが調べることはできません。

### DB固有の制限

- `master.db` のCUE色は変換していません。位置・名前・ループを保持し、色がある場合は警告します。HOT CUE I以降と未対応のCUE種別は警告して省略します。
- 終了位置が保存されていないループは、平均BPMから長さを推測せず省略します。必要なループはXML経由で取り込んでください。
- 条件式で生成するスマートプレイリストは警告して省略します。通常プレイリストの重複曲は1件へまとめます。
- ローカルパスや長さがないストリーミング専用の曲は取り込みません。
- アルバム、ジャンル、キー、レーティング、Phrase、アートワークなど、上表にない情報は引き継ぎません。

## 音源と既存ANLZの照合

フォルダからの取り込みでは、DB／XMLに記録されたパスを選択範囲内のファイルと照合します。移動したフォルダには、フォルダ名を含む一意な末尾パスで対応します。同じファイル名だけを頼りに音源を割り当てず、曖昧な場合は未関連付けのまま残します。音源サイズがDBにある場合はサイズも確認します。

DBが参照する `ANLZ0000.DAT`／`.EXT` を選択範囲から読み、波形のピークとビートグリッドを引き継ぎます。ANLZ内の音源パスも照合します。PCキャッシュの `?/ファイル名` は、DBが指定した解析ファイルへの対応が取れた場合だけ許可し、音源をファイル名検索するためには使いません。競合するグリッド、別の音源への参照、破損した解析ファイルは警告し、その解析データを採用しません。波形はDECKFLOWの表示用ピークへ変換するため、rekordboxの色波形をそのまま再現するものではありません。

`master.db` のCUEを正本とし、空のCUE一覧を持つPC側ANLZで上書きしません。DECKFLOWで編集した準備情報も保持します。XMLのみの取り込みではANLZの参照がないため、音源を関連付けると表示用波形を作成します。

## キャッシュと再読み込み

メタデータ、解析済みの読み取り結果、音源、読み込み元の情報をIndexedDBへ保存します。音源は元の圧縮／符号化形式のままコピーし、フォルダ取り込み時には全曲デコードしません。保存完了した曲は、USBを外したあとも左側の読み込み元から開けます。

同じ読み込み元を更新するときは **ライブラリを開く → 保存したライブラリの「再読み込み」** を選び、元フォルダを選び直します。DB内容のSHA-256が同じなら保存済みの読み取り結果を再利用します。既に保存した音源は再コピーせず、元音源のサイズ・更新時刻等に変化があれば警告して保存済み音源を保持します。

取り込みは**追加方式**で、自動同期ではありません。既存曲の編集、CUE、保存音源、既存プレイリストを保持します。元側での削除・変更も自動反映しません。変更されたDBを新しい読み込み元として開くと別ライブラリになる場合があるため、同じ読み込み元には「再読み込み」を使ってください。「一覧から外す」は読み込み元の参照だけを外し、保存した曲は残します。

試聴とDJデッキは、同じ曲のデコード結果を共有します。PCMキャッシュは最大2件・合計96 MiB、読み取り／デコードは同時に1件ずつ処理し、重複要求はまとめます。大きすぎるPCMは再生用に返しますがキャッシュに保持しません。96 MiBは**キャッシュだけの上限**で、デッキ・スクラッチ・デコード中のメモリを含む総使用量ではありません。一覧は75曲ずつ表示し、検索と並べ替えはライブラリ全体に適用します。端末別の速度改善率や音声遅延を計測済みとするものではありません。

取り込みを中止したり一部の音源が見つからなかったりした場合も、保存済みの曲情報と音源は残ります。再読み込みで未保存の音源を続けて関連付けられます。ブラウザがIndexedDBを使えない場合は一時保存であることを表示します。ブラウザのサイトデータ削除や保存領域の削除に備え、元DB・音源は保管してください。

## XMLだけを読み込む・音源を関連付ける

rekordboxの「コレクションをXML形式でエクスポート」で保存したUTF-8 XMLを、**ライブラリ操作 → rekordbox XMLを取り込む** から選ぶか、XMLを1つドラッグ＆ドロップします。XML中のファイルURLへ自動アクセスすることはありません。

同じ元TrackIDとLocationに基づいて既存曲を判定します。新しい曲とプレイリストを一括保存し、既存項目の編集を保持します。同じ階層・名前・曲順のプレイリストは重複せず、曲順や収録曲が変わったXMLのプレイリストは別のものとして追加します。

音源未関連付けの曲には **音源を選択** と表示します。**音源を追加** で複数の元音源を選ぶこともできます。

- この個別ファイルの関連付けでは、ファイル名、曲長（整数秒のXML等に対し1.1秒以内）、記録されている場合はサイズを確認します。
- 同名・同じ長さの候補が複数あるときは自動で選ばず、曲ごとの「音源を選択」で指定します。
- BPMを再解析せず、CUE・テンポ区間を保持して、曲長をデコードした実長へ更新します。表示用波形は必要に応じて音源から作成します。
- CUE／LOOPが実音源の終端を超えている場合は関連付けを停止します。すでに保存した別音源を曲名だけで上書きしません。

曲情報でメモリーCUE／LOOPの名前・位置を確認でき、HOT CUE A〜HとHOT LOOPはDJデッキで操作できます。各TEMPO区間に合わせてデッキのBPM表示、グリッド描画、拍数ループを計算します。試聴のBPM欄は平均BPMに基づきます。SYNCは押した時点のBPM合わせで、継続的なテンポ追従や拍位相の自動整列ではありません。

## 既存ANLZの波形をUSBへ引き継ぐ

Web版へ取り込んだ表示用ピークだけでは、CDJ向けANLZファイルを再現できません。USBへ既存ANLZを引き継いで書き出すときは、Mac補助ツールに元のANLZフォルダを指定します。アプリから保存したライブラリJSONと、元音源も必要です。

```sh
npm run usb:export -- \
  --library /path/to/deckflow-library.json \
  --audio-dir /path/to/Music \
  --analysis-dir /path/to/USBANLZ \
  --out /path/to/DECKFLOW-NEW-EXPORT
```

ANLZのPPTHと、XMLに記録された元Locationまたは現在の元音源の絶対パスが一致する解析ファイルを選びます。ファイル名だけで波形を流用しません。選んだDAT／EXT／2EXを一時フォルダへコピーし、出力先パスとCUEを更新します。元ANLZは読み取り専用で扱います。古いキャッシュで2EXがない場合は、その状態で引き継ぎます。

フルパスが記録されず `?/曲名` などになっているキャッシュは、対応を明示するJSONを作ります。曲IDはDECKFLOWのライブラリJSONの `tracks[].id` を使います。

```json
{
  "format": "deckflow.analysis-map",
  "version": 1,
  "tracks": {
    "rb-track-example": "P001/00000001/ANLZ0000.DAT"
  }
}
```

コマンドに `--analysis-map /path/to/analysis-map.json` を追加してください。パスは `--analysis-dir` 配下からの相対パスです。明示指定でも、ビートグリッドと曲長の検証は省略しません。

一致する解析ファイルがない曲は新しく生成します。一致したファイルのグリッドに矛盾がある場合や、候補が複数ある場合は停止し、黙って再生成しません。出力後は波形セクションとPQTZ／PQT2のSHA-256を原本と比較します。各曲の `analysis.status` が `reused` か `generated` か、理由と原本のハッシュを `DECKFLOW-REPORT.json` に記録します。

## サイズ・形式の制限

- ライブラリDBは128 MiB、XMLは32 MiB、最大10,000曲・1,000プレイリスト。音源の80 MiB／20分制限は撤廃し、USB／フォルダからは大容量音源も全体デコードせずBlobとして保存します。保存容量が不足した場合はエラーを表示し、その曲の保存を取り消します。
- 1 GiB級RIFF WAVは部分読み取りで試聴・DJ再生・解析します。PCM8／16／24／32-bit、float32／64-bit、WAVEFORMATEXTENSIBLEに対応。RF64・BW64・RIFX・圧縮WAVは未対応、他形式はブラウザのデコード能力に依存します。多チャンネル音源の再生は先頭2ch、曲情報の最大長は24時間です。
- Mac helperはDevice LibraryとOneLibraryを同時生成し、両DBを読み戻します。従来PDBのサイズ・曲長フィールドに合わせ、USBへの書き出しは4 GiB未満・65,535秒以内です。[1 GiB級音源での実書き出し検証](usb-large-audio-2026-11-07.md)を参照してください。
- Webで選択するフォルダは100,000項目・階層32まで。ブラウザで読むANLZは1ファイル32 MiBまでです。
- 平均BPMは30〜300、TEMPO区間は20〜600。ANLZからのグリッド取り込みは4拍の小節に対応します。
- XMLの空フォルダーは警告して省略します。空プレイリストは保持します。POSITION_MARKはCUE (0)／LOOP (4) に対応し、Fade-In／Fade-Out／Load (1〜3) は対応エラーになります。DTD・外部エンティティ・不正な参照も保存前に拒否します。
- 直接DB取り込み、XML取り込み、通常の音源追加で登録した曲を横断して自動統合する機能はありません。XMLの元Location／TrackIDが変わると別曲になります。
- 曲情報で平均BPMを変更しても取り込んだビートグリッドは変更しません。グリッド編集画面とメモリーCUEの編集／呼び出し操作は未実装です。
- MacのUSB書き出しは4/4拍子に対応します。HOT CUEのRGBはbakenのCDJ用16色へ近似します。メモリーCUEのRGBはwriterが保持できないため、色が指定されている場合はUSB生成前に停止します。名前の先頭の `[active]` はアクティブループ指定として扱い、出力表示名には含めません。
- Mac補助ツールのANLZ探索は100,000項目・階層12・DAT走査512 MiB、解析ファイル1個64 MiBまで。同名曲の同時USB書き出しや曖昧な音源パスは停止します。
- 物理iPadでの外部USB／フォルダ選択・音声遅延・長時間動作、CDJ-3000実機の表示・音出し・Quantizeは未検証です。DB readerの対応は、rekordbox全バージョン・全USB機種への互換保証ではありません。

形式の根拠と採用コード：[rekordbox公式XML仕様](https://cdn.rekordbox.com/files/20200410160904/xml_format_list.pdf)、[OneLibraryの固定ソース](https://github.com/v1vendi/onelibrary/tree/02c6f80c802a635c394e733058502ecf28cf9fc9)、[固定版bakenのANLZ書き換え](https://github.com/M-Igashi/baken/blob/50d2ba07fdad49d3a95e02d2951ac7a67197e85a/crates/baken-export/src/anlz/rewrite.rs)。ライセンスと変更内容は [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) を参照してください。
