# rekordbox XMLと既存波形の取り込み

rekordboxで準備した情報を、BPMの再解析をせずDECKFLOWへ引き継ぎます。rekordbox本体のコードや音源を同梱する機能ではありません。

## XMLを読み込む

rekordboxの「コレクションをXML形式でエクスポート」で保存したUTF-8 XMLを、楽曲管理の「rekordbox XMLを取り込む」から選びます。曲がある場合は「ライブラリ操作」を開きます。1ファイルのドラッグ＆ドロップにも対応します。

| データ | 対応 |
| --- | --- |
| 楽曲 | 曲名、アーティスト、平均BPM、長さ、追加日、元のLocation／TrackID／Size |
| ビートグリッド | 複数TEMPOの開始位置、BPM、拍子、小節内の拍番号 |
| CUE | HOT CUE A〜H、メモリーCUE、メモリー／HOT LOOP、名前、RGB色 |
| プレイリスト | 曲順、階層、空のプレイリスト、同名のプレイリスト |

同じ曲IDと元Locationに基づき既存曲を判定します。既存曲のメタデータ・音源は更新せず、新しい曲とプレイリストを一括保存します。同じ階層・名前・曲順のプレイリストは重複しません。曲順や収録曲が変わったXMLは別プレイリストとして追加します。

元のXML内のファイルURLへアクセスしたり、音源を自動取得したりすることはありません。

## 音源を関連付ける

XMLはメタデータだけなので、取り込み直後の曲には「音源を選択」と表示します。「音源を追加」から複数の元音源を選ぶこともできます。

- 自動照合にはファイル名、曲長（整数秒のXMLに対し1.1秒以内）、XMLに存在する場合はSizeを使います。
- 同名・同じ長さの候補が複数あるときは自動で選ばず、曲ごとの「音源を選択」で指定します。
- BPM解析を呼ばず、表示用ピーク波形だけを音源から生成します。CUE・テンポ区間はそのまま残し、曲長はデコードした実長へ更新します。
- 元のCUE／LOOPが実音源の終端を超えている場合は関連付けを停止します。
- 曲名だけを根拠に、すでに登録した別の音源を上書きすることはありません。

曲情報ダイアログではメモリーCUE／LOOPの名前・位置を確認できます。HOT CUE A〜HはDJデッキから操作でき、取り込んだHOT LOOPはループとして再生します。各TEMPO区間に合わせてデッキのBPM表示、グリッド描画、拍数ループを計算します。SYNCは押した時点のBPM合わせで、継続的なテンポ追従や拍位相の自動整列ではありません。

## 既存ANLZの波形をUSBへ引き継ぐ

XMLにはrekordboxの波形バイナリは含まれません。Mac補助ツールに既存のANLZフォルダを指定します。アプリから保存したライブラリJSONと、元音源も必要です。

```sh
npm run usb:export -- \
  --library /path/to/deckflow-library.json \
  --audio-dir /path/to/Music \
  --analysis-dir /path/to/USBANLZ \
  --out /path/to/DECKFLOW-NEW-EXPORT
```

ANLZのPPTHと、XMLに記録された元Locationまたは現在の元音源の絶対パスが一致する解析ファイルを選びます。ファイル名だけで波形を流用しません。選んだDAT／EXT／2EXを一時フォルダへコピーし、出力先パスとCUEを更新します。元ANLZは読み取り専用で扱います。古いキャッシュで2EXがない場合は、その状態で引き継ぎます。

フルパスが記録されず `?/曲名` などになっているキャッシュは、対応を明示するJSONを作ります。曲IDはDECKFLOWのライブラリJSONの `tracks[].id` を使います。

```json
{
  "format": "deckflow.analysis-map",
  "version": 1,
  "tracks": {
    "rb-track-example": "P001/00000001/ANLZ0000.DAT"
  }
}
```

コマンドに `--analysis-map /path/to/analysis-map.json` を追加してください。パスは `--analysis-dir` 配下からの相対パスです。明示指定でも、ビートグリッドと曲長の検証は省略しません。

一致する解析ファイルがない曲は新しく生成します。一致したファイルのグリッドに矛盾がある場合や、候補が複数ある場合は停止し、黙って再生成しません。出力後は波形セクションとPQTZ／PQT2のSHA-256を原本と比較します。各曲の `analysis.status` が `reused` か `generated` か、理由と原本のハッシュを `DECKFLOW-REPORT.json` に記録します。

## 現在の制限

- XMLは32 MiB、10,000曲、1,000プレイリストまで。Webでの音源読み込みは1曲80 MiB・20分までです。
- 平均BPMは現在のライブラリに合わせて30〜300、TEMPO区間は20〜600です。アルバム・ジャンル・キー・レーティングなど、上の表にない属性は取り込みません。
- 空のフォルダーは警告を表示して省略します。フォルダー内の空プレイリストは保持します。
- POSITION_MARKはCUE (0)／LOOP (4) に対応します。Fade-In／Fade-Out／Load (1〜3) は対応エラーとし、取り込み全体を停止します。DTD・外部エンティティ・不正な参照を含むXMLも保存前に拒否します。
- 元LocationとTrackIDが変わると別曲として追加します。通常の音源読み込みで先に追加した曲との自動統合はしません。
- 曲情報で平均BPMを変更しても、XML由来のグリッドは変更しません。グリッド編集画面とメモリーCUEの編集／呼び出し操作は未実装です。
- USB書き出しのグリッドは4/4拍子に対応します。HOT CUEのRGBはbakenのCDJ用16色へ近似します。メモリーCUEのRGBはwriterが保持できないため、色が指定されている場合はUSB生成前に停止します（XML取り込み・ライブラリ保存では保持）。名前の先頭の `[active]` はbakenのアクティブループ指定として扱い、出力表示名には含めません。
- ANLZ探索は100,000項目・階層12・DAT走査512 MiBまで、解析ファイル1個は64 MiBまで。範囲を超える場合は対象フォルダを絞ってください。
- 同名曲の同時USB書き出しや曖昧な音源パスは停止します。音源フォルダとセットを分けてください。
- CDJ-3000実機の表示・音出し・Quantize、物理iPadでのファイル選択は未検証です。

形式の根拠：[rekordbox公式XML仕様](https://cdn.rekordbox.com/files/20200410160904/xml_format_list.pdf)、[固定版bakenのANLZ書き換え](https://github.com/M-Igashi/baken/blob/50d2ba07fdad49d3a95e02d2951ac7a67197e85a/crates/baken-export/src/anlz/rewrite.rs)。配布する独自パーサーは外部ネットワークへ接続しません。
