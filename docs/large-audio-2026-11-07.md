# 大容量音源・CDJ USB互換性の修正（2026-11-07）

「1曲80 MB以内」という拒否はアプリ独自の制限でした。通常追加、既存ライブラリの音源キャッシュ、デッキ、試聴に重複していた80 MiB／20分制限を撤廃しました。

上限値の削除だけでは、1 GiB WAVを読み込む際に元ファイル全体、デコードPCM、スクラッチ用PCMを同時に持つため、端末のメモリを圧迫します。大容量RIFF WAVを部分読み取りする経路へ変更しています。

## 実装

- WAVヘッダーはBlobの範囲読み取りで解析します。未知のRIFFチャンクの内容を読み込まずスキップし、破損した長さ・フレーム幅・拡張形式を拒否します。
- ファイル選択から取得したFileをそのままIndexedDBへ保存すると、原本削除後に読めなくなることをChromeで再現しました。音声バイト列を1 MiBずつ所有コピーし、保存完了時に曲情報と参照を切り替える方式へ変更しました。元ファイル削除後の読み戻しも実ブラウザで検証しました。既存形式のBlobは引き続き読めますが、旧版で保存し原本を失った音源を復元する機能ではありません。
- ファイルサイズまたはデコードPCM見積が32 MiBを超えるWAVはファイル参照を保持します。32 MiBは経路の切替値で、入力サイズ上限ではありません。
- デッキ・試聴・スクラッチは32768フレーム単位で必要なPCMを読みます。大容量ファイルを全体デコードせず、ページの保持数と同時読込数を固定します。停止・曲変更・削除後の遅延結果は採用しません。
- BPMは先頭・中間・末尾の各40秒以内を独立してWorkerで解析します。標本間の空白を拍の間隔に数えず、位相を曲の時刻へ補正します。取り込み元のBPM・CUE・ループを再関連付けで上書きしません。
- 取り込み直後の全体波形は900区画の標本です。試聴／デッキ読み込み後に、全音声を小さなチャンクでWorkerへ渡して詳細波形を生成します。最大30万フレームの派生データとして保存し、元音源は変更しません。
- USB helperはDevice LibraryとOneLibraryを両方生成します。WAVの実サンプルレート／ビットレートをXMLとPDBへ渡し、出力の両DB、プレイリスト、CUE、音源ハッシュを照合します。[USB検証記録](usb-large-audio-2026-11-07.md)

## 検証方法

`tests/large-audio.browser.mjs` はlocalhostの使い捨てChromeプロファイルで実ファイルを選択します。テスト音源は1,073,741,824 bytes、48 kHz、16-bit stereo、約93分12秒の疎ファイルで、一部に合成120 BPM・逆相ステレオ音を含みます。ユーザーの音源は使用しません。

取り込み、BPM／波形、IndexedDBのBlobサイズ、元ファイル削除後の再読み込み、試聴、デッキ再生、途中へのシーク、ループ、テンポ変更、KEY LOCK、スクラッチ、同時2デッキ、解放を確認します。画面上の時刻だけでなく、実AudioWorkletからの音声出力もチャンネル単位で検査します。元ファイル全体への`decodeAudioData`呼出しがないことを記録します。

通常の単体テストに加え、破損WAV、EOF、遅延読込、取消し、書き込み失敗、ページ境界、サンプルレート変換、再読み込み時の準備情報保持を回帰テストに含めます。

## 検証結果

- [Nodeテスト](large-audio-2026-11-07/tests.txt): 264件成功、失敗なし、1件スキップ。スキップ対象の大容量USB書き出しは別の実行で成功しました。
- [Chrome 156実行記録](large-audio-2026-11-07/browser.txt): 1 GiB／約93分12秒のWAVを追加し、120 BPMと解析。原本削除・再読み込み後の試聴、全268,435,445サンプルフレームからの詳細波形生成・永続保存、途中シーク後の実音声出力、ループ、テンポ変更、スクラッチ、同時2デッキを確認しました。オフラインで再読み込みして保存音源を再生でき、ページ例外はありませんでした。
- [保存回帰の実行記録](large-audio-storage-2026-11-07.txt): 容量不足・読み取り失敗・中止・別タブからの編集／削除／差し替えを含む16項目成功。保存失敗時に旧データを保持し、一時データを除去することを確認しました。
- [カバレッジ](large-audio-2026-11-07/coverage.txt): Nodeで読み込まれた27個のdistモジュールが対象です。ブラウザ専用コードを含むプロジェクト全体の値ではありません。

Web Locks対応環境では、次の音源保存時に中断したコピーの一時データを回収します。非対応環境でも通常の失敗・中止は後始末しますが、ブラウザ強制終了時の一時データは他タブの作業を保護するため自動削除しません。

実行例（Playwrightは外部の検証用インストールでよく、Webアプリの実行依存には追加しません）:

```sh
PORT=4187 npm run dev
DECKFLOW_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/large-audio.browser.mjs
```

## 対応範囲

| 項目 | 今回の対応と残る範囲 |
| --- | --- |
| 大容量音源 | 1 GiB級RIFF WAVの部分読込。PCM8／16／24／32、float32／64、WAVEFORMATEXTENSIBLE。実再生確認はmono／stereoで、3ch以上は先頭2ch |
| 他の音源形式 | MP3／AAC／FLAC等はブラウザのデコード能力に依存。RF64／BW64／RIFX・圧縮方式WAVは未対応 |
| 保存 | IndexedDBの実容量まで。容量不足時はその曲の保存を取り消し、エラーを表示。ライブラリのメタデータ検証は24時間以内 |
| rekordbox／USB読み取り | master.db、export.pdb、exportLibrary.db、XMLと既存ANLZを読み取り。元ファイルは変更しない |
| CDJ USB書き出し | Mac helperで両DBを新規フォルダへ生成・読み戻し。従来PDBのフィールド幅により4 GiB未満・65,535秒以内 |
| USBの運用 | 既存USBへの追記・上書き、フォーマット、履歴の逆同期、iPad単体のUSB生成は未実装 |
| rekordboxとの機能差 | メモリーCUE操作、ビートグリッド編集、拍位相SYNC、スマートプレイリスト、STEMS、独立ヘッドホン出力等は未実装 |
| 実機 | 物理iPad・外部MIDI・CDJでの受入、音声遅延、長時間安定性は未確認。合成音源の結果は実曲・実機の性能保証ではない |

形式の根拠: [Microsoft WAVEFORMATEXTENSIBLE](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatextensible)。既存の全体デコード方式が完全なファイルを必要とすることは[MDN decodeAudioData](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData)も参照してください。

## 通信について

音源の取り込み・解析・再生・保存は端末内で処理します。Vercelへの音源アップロード、外部解析API、曲データの定期送信はありません。初回のアプリ資産ダウンロードに加え、起動時などのService Worker更新確認や新しいアプリ資産の取得では通信します。キャッシュと音源保存が完了した後は、ネットワークを切って利用できます。初回以外の通信を一切行わない設計ではありません。
