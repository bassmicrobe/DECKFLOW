結果

集計範囲と限界
従来の Node --test --test-coverage-include='dist/**' --test-coverage-exclude='dist/vendor/**'
と同じ27ファイルを対象とした。低いファイルを取り除く追加除外は行っていない。
app.js やブラウザ専用Worker、通常のfile URLでロードされないVM内のWorkletは、このNode集計に入らない。
VMでWorkletを実行するテストの合否と、そのソースのカバレッジ帰属は区別する。
vendor、tools、testsも対象外。--allで未ロードソースをゼロとして加えたプロジェクト全体の値ではない。
Chromeで実施したIndexedDB/Web Locks/ブラウザ操作の到達分は、この数値に加算していない。
個別の audio-chunk-store.js、library-store.js の行率や waveform-cache.js の関数率は80%未満のまま掲載する。
したがって「全ファイル80%以上」や「ブラウザを含む全コードの90.74%」を意味しない。

Node標準レポートとの差の原因
同じファイルの無クエリURLと ?v=... URLが10モジュールで共存し、37 URLが27実ファイルを指した。
Node v24.16.0 の internal/test_runner/coverage は mergeCoverage 内で完全なURLをキーとして合成し、
summary表示ではfileURLToPath(url)へ戻すため、別URLの到達数が同じ実ファイルとして合成されない。
最終版前の調査では、ソースを変えない再実行で標準表の audio-resource.js が15.63%から98.75%へ変わり、
逆にfile-drop.jsが16.92%となった。標準表の同一path表示だけでは正しい合算を確認できない。
この二重URLの生データをそのまま80%ゲートの根拠にしない。

実施した最終測定
1. rootが最終build後、次のコマンドで全Node suiteを一度実行して生V8 coverageを採取した。
   NODE_V8_COVERAGE=/tmp/deckflow-large-final-v8 DECKFLOW_BAKEN_BIN="$PWD/.local/baken/bin/baken" node --test tests/*.test.mjs
   265 tests: 264 pass / 0 fail / 1 skip。途中中断なし、実行時間9163.70ms。
   新たなwaveform保存領域のタイムアウト後再試行、同期open例外、blocked/error後復旧の2件も成功。
   残るskipは DECKFLOW_LARGE_AUDIO_TEST=1 が必要な実1 GiB USB出力テスト。
   実1 GiB USB検証の別実行結果は他の検証資料を参照。
2. この最終実行の /tmp/deckflow-large-final-v8 だけを集計。以前の実行やUSB補完採取データは混ぜていない。
   file URLをfileURLToPathで正規化（query/hashを除去）し、@bcoe/v8-coverage mergeProcessCovsでrangeを合成。
   当該実ソースの範囲内にoffsetが収まることを確認。dist対象のcoverageを含む28 process reportを合成。
3. v8-to-istanbul/c8で表示。独立にc8へ元の生データを直接渡した結果とも、全27件のJSON summaryが完全一致。
   c8自身もfileURLToPath正規化後に@bcoe/v8-coverageで合成する。
   line/function/branchがいずれも80%以上であることを数値検査し成功。

  npm install --prefix "$TASK_COVERAGE_DIR/tools" --no-audit --no-fund --ignore-scripts c8@12.0.0 @bcoe/v8-coverage@1.0.2 v8-to-istanbul@9.3.0
  DECKFLOW_BAKEN_BIN="$PWD/.local/baken/bin/baken" NODE_V8_COVERAGE="$TASK_COVERAGE_DIR/raw" node --test tests/*.test.mjs
